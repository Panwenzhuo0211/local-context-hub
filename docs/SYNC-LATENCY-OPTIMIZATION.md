## 修改与保证范围

- 已完成的 Codex JSONL 记录立即进入增量投递，用户消息无需等待完整回答。
  生成状态另存于同步日志，重启后仍禁止向正在生成的目标追加外部消息。
- 无变化时复用文件身份、大小和时间对应的验证结果；变化时流式校验已消费
  前缀的完整 SHA-256，再读取新增部分。没有缓存整份数百 MiB 历史。
- ZCode 已确认内容块由 SQLite 关联同步日志过滤，避免逐轮取出并解析全文。
- Hub 镜像从最后一轮延伸分页索引。真正的 Codex 原会话只追加外来投递的
  索引，不删除、重建或重新编号已有原生轮次和工具记录。
- 原生文件换段后的全局编号可从非零开始；只有目标分页水位确实追上当前
  文件时才追加。索引滞后显示等待，失败有持久化重试，原始会话回退会阻止同步。
- 修复“导入后过一段时间才启用”的缺口：根据匹配的导入凭证和完整摘要，
  补齐源端以及副本中期间新增的记录。错误来源凭证不能建立绑定。
  新 ZCode 导出清单同时保存原内容块摘要，反向流程也能补齐导出后的新增。
  旧清单缺少内容块基线且来源已变时要求重校验，避免静默漏掉消息。
- 状态报告等待目标空闲、等待原生索引、等待源端消息完成，以及待投递数量、
  单次检查耗时和最近投递时间。保留窗口显示/模型读取未验证标识。

## 操作与剩余边界

指令例子和绑定说明见 [同步说明](SESSION-SYNC.md)。导入凭证保存来源关系，
单独导入不创建活跃同步绑定。明确授权后，以两端会话 ID 建立一对一绑定；
不会按标题猜测、自动连接所有副本，也不会触发对端模型工作。

源记录被改写、ZCode 回退或 Codex 权威文件切换时，需要重新核对基线。
某些实际换段会重用被中断轮次的编号，不能仅凭同一会话 ID 自动合并。
文件追加与客户端数据库没有共同事务；重试和身份检查降低风险，但没有
与两款客户端达成跨进程写入协议。因此同步仍为实验功能。

热刷新、活跃模型内存更新、下一轮模型自动读入这三个环节未通过本轮验证。
这轮没有宣称完全实时双向共同会话。
