# 原生上下文启动性能（2026-10-25，v4）

用户要求当前聊天读入与原生副本创建均尽可能快；十秒左右是性能目标，
不是以遗漏历史或削弱校验换取的硬性上限。普通加载仍只读，导入和同步分别明确选择。

## 本机实测

| 场景 | 耗时 | 验证范围 |
| --- | ---: | --- |
| 约 774 MB Codex 历史，首次读入当前聊天 | 8.52 秒 | 校验两个续接文件；返回最近 20 条，明确更早尚有 8,128 条 |
| 同一来源再次读取 | 0.15 秒 | 索引复用；返回内容和来源水位一致 |
| 真实 ZCode 会话创建 Codex 原生副本 | 0.52 秒 | 完整导出所选会话，并保留原始时间 |
| 上述 Codex 副本经安装客户端原生接口读档 | 0.29 秒 | 103 轮、493 条文本，顺序和最新文本与导出结果一致 |
| 大型 Codex 来源完整导入 ZCode | 16.21 秒 | 4,892 条消息、4,925 个内容块、3,257 条原始工具调用、33 个图像块 |
| 上述 ZCode 副本经安装客户端原生接口启动和读档 | 10.85 秒 | 最近 20 条顺序和最新时间与来源一致，包含 16 个工具块 |

两个方向分别合计约 **0.81 秒**和 **27.05 秒**。这些是本机单次样本，
使用新的 Hub 索引或附件缓存；没有清空操作系统文件缓存。原生接口读档不等于
桌面窗口完成绘制，模型生成响应的耗时也未计入。验证没有发起模型回合。

## 修改

- 不再把重复的传输事件重新编码为 JSON 来做语义摘要；源文件的全部字节仍
  接受完整摘要校验，真正的对话记录仍检查身份、冲突与续接关系。
- 将大的原始工具结果完整存入一个不可变 JSONL 容器，替代上百次单独建文件、
  写盘和重复序列化。所有记录和图片保留；会话中的长内容以明确预览和引用呈现。
- 容器落盘后完整回读校验，再发布原生数据库事务。补读附件会再次核对记录
  摘要、边界与指定字段；`read_native_payload` 和 `native-payload` 支持分页。
- 仅在可丢弃的临时数据库关闭日志和同步写入。真正的原生数据库仍使用事务、
  完整性比对和既有恢复保护，失败时不覆盖用户已有会话。
- 原生行的指纹采用带类型和长度的 SHA-256 输入，避免再次转义大段 JSON。
  旧版指纹回执仍可验证，同长度本地修改也会阻止覆盖。
- 用户已明确指定来源会话时，一次只读调用即可定位和加载，无需先刷新归档。

## 检查与限制

**117 项测试通过**，包括批量附件逐页还原、篡改检测、跨记录边界检测、
旧回执兼容、同长度本地修改保护、隐藏提示过滤、来源续接和失败恢复。

Codex 原生读档使用该安装版本支持的完整历史接口；它的分页条目接口在本次
独立 CLI 进程中未实现。因此没有把分页接口成功或桌面热刷新列为已验证结果。
接收方已打开窗口的刷新、正在运行的模型是否读到外部追加，继续保持未验证。

私人执行回执保存在 Hub 数据目录的 `validation/native-startup-*.json`；
其中引用了来源与测试副本标识，不写入源码仓库。所有真实来源测试只读进行，
原生副本写入隔离目录，没有导入到用户正在工作的会话或开启同步。
