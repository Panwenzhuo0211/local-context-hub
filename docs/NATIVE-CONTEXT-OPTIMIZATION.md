# 原生上下文接续优化（2026-10-25，v3）

普通加载在当前聊天只读进行。导入原生副本和同步仍为分别明确启用的操作。

## 按名称加载

`read_session_context` 的 `session` 既支持 `adapter:会话ID`，也支持完整原话：

> 加载在 zcode 的《会话名称》会话的原生上下文

工具直接查询已接入来源的原生会话标题。唯一精确匹配才读取；同名返回
`ambiguous`，仅部分匹配返回 `candidates`。候选包含来源、标题、目录和更新时间。
不会因为某个同名会话较新就自动选择，不用全文搜索摘录冒充原生记录。
来源不可访问时明确返回错误；不创建事项、镜像或同步配对。

## 已读范围与分页

`coverage` 分开说明来源校验和本次实际返回范围，包括总记录数、索引范围、
前后尚未返回的记录数、是否在本次响应中包含全部历史。图片摘要和超出响应
预算的记录均明确列入 `pending_full_records`。模型需要补读后才能引用其完整内容。

索引缓存只保存记录位置和校验信息，不复制完整对话正文。源文件的身份、
大小、修改时间和当前原生来源变化会使缓存失效；补读的原始记录还要校验摘要。
ZCode 的分支、原始记录和当前状态同样参与检查。跨页补读不会覆盖旧页引用。

## 显式导入

`prepare_resume` 仅用于用户明确要求导入副本。只有来源未变、镜像内容摘要
一致时才复用；来源更新、镜像有本地续写或修改、缺少可信摘要时生成新副本，
保留旧镜像。结果明确说明生成副本并不等于当前模型已加载其上下文。

## 受管服务更新

部署时最后发布 `runtime-generation.json`，其中记录包内 Python 文件的摘要。
已加载 v3 的服务在工具调用间隙验证更新并载入新工作模块，发送标准
`notifications/tools/list_changed` 通知。当前调用会完成后再换版本；校验或载入
失败时保留已运行服务并在状态中报告错误。小型重载入口自身的更新仍需重启。

已经运行的 v2 服务不含这个入口，首次升级至 v3 仍需在客户端重启一次
Context Hub。通知是否立即更新桌面显示由客户端决定；这不是聊天内容实时同传。
